# Dynamic robots.txt on Forge

The robots document is generated by Laravel so each indexed tenant references
its own canonical sitemap and preview hosts do not advertise a sitemap.

Forge's static default location can retain a 404 status even while its error
handler renders the Laravel response. Cloudflare then supplies an empty managed
robots document, dropping the application's crawler rules.

In the Forge site's nginx configuration, replace only the exact robots location:

```nginx
location = /robots.txt {
    access_log off;
    log_not_found off;
    try_files $uri /index.php?$query_string;
}
```

Do not force the global `error_page` handler to return 200: missing application
pages must continue to return 404. Validate nginx configuration before reloading
through Forge. The current shared configuration is
`/etc/nginx/forge-conf/3094000/site.conf` and affects the tenant server blocks.

After applying the configuration, verify the HTTPS origin with hostname/TLS
validation and then verify the public Cloudflare URL. Both must return 200 and
contain `User-agent: *`, the private-route exclusions, and the tenant's real
`sitemap.xml` directive. Cloudflare Origin CA certificates require the official
Cloudflare Origin CA trust chain for a direct-origin curl; do not disable TLS
verification. Also verify an unknown URL still returns 404 and a preview host
does not expose an indexable sitemap.
