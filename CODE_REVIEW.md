## Top priorities (fix first)

1. **Stripe webhook accepts forged events** — the custom route skips signature verification; an attacker can grant themselves credits/subscriptions. (SEC-2)
2. **Admin platform-config routes missing the `admin` middleware** — any logged-in user can rewrite global platform config. (SEC-1)
3. **Live DB password committed to git** in `phpunit.integration.xml`. (SEC-8)
4. **Metered ad-spend billing is a dead API call** — `recordUsageFor` doesn't exist in Cashier v16; every subscriber is invoiced $0 for ad spend, silently, daily. (BILL-1)
5. **Pause/recovery dead-ends** — a payment-failed customer is never auto-recovered, and paying the recovery charge takes money but never resumes their campaigns. (BILL-2)
6. **Unclamped LLM budgets pushed live monthly** — `ApplySeasonalStrategyShift` writes a Gemini-generated `new_daily_budget` straight to the platform with no bounds check; one hallucination = a $5k/day live budget. (JOB-1)
7. **Attribution + Campaign Copilot 403 for everyone** — ownership check reads a dropped column (`customers.user_id`). (DATA-1)
8. **Billing has no idempotency or row-locking** — retries/concurrent runs double-charge cards and corrupt the balance ledger. (BILL-3)
9. **MCC refresh-token encryption gap** — token used raw in 4 conversion-upload paths; encrypting it at rest (which the admin UI already does on save) silently breaks all server-side conversion uploads. (DATA-2)

## 1. Security & authorization

- **SEC-1 (P0) — Admin platform routes not gated by `admin`.** `routes/web.php:297` group is `['auth']` only (every other admin block is `['auth','admin']`). `EnabledPlatformController` does no internal authz, so any authenticated user can create/edit/delete/toggle global `EnabledPlatform` config (disable all ad platforms tenant-wide). **Fix:** move these routes into the `['auth','admin']` group.
- **SEC-2 (P0) — Stripe webhook unsigned.** `routes/api.php:7` → `StripeWebhookController` without `VerifyWebhookSignature` middleware; Cashier does verification only in that middleware. Forged `checkout.session.completed`/subscription events grant credits and active subscriptions. **Fix:** attach `VerifyWebhookSignature` (secret already in env) and stop logging the full payload.
- **SEC-3 (P1) — IDOR in `GTMSetupController`** (all methods) and **SEC-4 (P1) — IDOR in `CustomerPageController::index`** — no check that the user owns the route-bound `{customer}`; cross-tenant read + writes (`firstOrCreate`). **Fix:** `abort_unless($request->user()->customers()->where('customers.id',$customer->id)->exists(),403)` at the top of each method (the pattern used correctly elsewhere).
- **SEC-5 (P2) — Path traversal in report download.** `ReportController::download` interpolates unvalidated `$period`/`$date` route params into a filesystem path; `../` escapes the customer's report dir. **Fix:** allowlist `period`, regex-validate `date` as `Y-m-d`, reject `..`/`/`.
- **SEC-6 (P2) — Sensitive data logged.** Full Stripe payload (`StripeWebhookController:24`), full `$request->all()` on deploy (`DeploymentController:23,70`) and OAuth callback (`YouTubeAuthController:42,62`, captures `code`/`state`). **Fix:** log allowlisted non-sensitive keys only.
- **SEC-7 (P2) — Invitation auto-login, no expiry.** `InvitationController::accept` calls `Auth::login()` for an existing user by email with a never-expiring token; a forwarded link = account takeover. **Fix:** expire tokens; require existing users to be authenticated before accepting.
- **SEC-8 (P0/hygiene) — Live DB password in git.** `phpunit.integration.xml` hardcodes a real `DB_PASSWORD` + host. **Fix:** move to CI secrets, scrub history, **rotate the credential**.
- **SEC-9 (P3) — GAQL string interpolation.** `SearchAudience.php:29` and other `CommonServices/*` interpolate keywords/resource names into GAQL. Low risk (AI-derived, read-only, own account) but a `'` breaks/injects. **Fix:** escape single quotes or validate charset.

_Verified sound: mass-assignment (uses `validated()`), Inertia shared props (no secrets), tracking endpoints (HMAC + replay window + rate limit), file-upload validation, Resend inbound HMAC._

## 2. Billing & payments

- **BILL-1 (P0) — Metered usage reporting broken.** `ReportAdSpendUsage.php:69` calls `$user->recordUsageFor(...)`, removed in Cashier v16 (only `reportMeterEvent` exists). Throws, swallowed, logged. Every subscriber's ad-spend usage → $0 invoiced daily. **Fix:** migrate to Stripe meter events; alert on the catch.
- **BILL-2 (P0) — Pause/recovery dead-ends.** `ProcessDailyAdSpendBilling` only selects customers with `active` campaigns, but pausing sets them `paused` → recovery branch is unreachable dead code. User retry/update-payment paths charge money and say "campaigns will resume" but never call `resumeAllCampaigns()`. Campaigns stay paused forever. **Fix:** drive the daily job off `adSpendCredit.payment_status`; have controller retry paths run the service so resume + budget-restore fire.
- **BILL-3 (P0) — No idempotency / no locking on charges or balance.** `chargeCustomer` (Cashier `charge()`) sends no Stripe idempotency key; `AdSpendCredit::deduct/addCredit` do unlocked float read-modify-write with no `DB::transaction`/`lockForUpdate`; `ProcessDailyAdSpendBilling` has `tries=3`. A mid-run crash re-deducts and re-charges every already-processed customer; concurrent top-up + daily bill lose updates. Also no unique index on `ad_spend_credits.customer_id` → duplicate accounts + double initial charge on racing deploys. **Fix:** per-(customer,date) completion marker; deterministic Stripe idempotency key; wrap mutate+ledger in a locked transaction; unique constraint + `firstOrCreate`.
- **BILL-4 (P1) — Unbilled spend silently written off.** When a shortfall charge fails, the delivered-but-unpaid spend is never recorded; the next day bills only new spend. **Fix:** track `outstanding_balance` (or allow negative balance) and roll it into subsequent charges/recovery.
- **BILL-5 (P1) — Half budgets forever after one failed charge.** Budgets cut to 50% on 2nd failure are only restored in the dead recovery path; the DB `daily_budget` and platform budget also diverge. **Fix:** restore budgets wherever `restoreAccount()` runs; store an immutable `pre_reduction_budget`.
- **BILL-6 (P1) — Currency: hardcoded USD in an AUD operation.** Credit rows created `'USD'`; no `CASHIER_CURRENCY`/`config/cashier.php` in repo (defaults `usd`); platform spend returns in each account's native currency and is deducted 1:1 with no FX. New sub-accounts + `DeployCampaign` hardcode `USD`. ~35% mispricing per dollar. **Fix:** set `CASHIER_CURRENCY`, store/enforce account currency on credit + per-platform, convert or refuse on mismatch.
- **BILL-7 (P1) — No spend reconciliation.** Billing reads exactly "yesterday" once at 08:00; if the sync is late/errored it records "no spend" as success and never revisits; Google restates cost for ~48h; Facebook fetched live for one day. No job compares cumulative platform spend to cumulative deductions. **Fix:** bill from a per-campaign-per-date ledger, re-scan a trailing 3–7 day window billing deltas, add a weekly reconciliation report.
- **BILL-8 (P2) — No markup/margin logic exists.** Managed billing passes platform cost through 1:1; the only margin hook (metered price) is broken (BILL-1). If the model assumes a %, it isn't implemented; if not, metered + credit deduction overlap must be made mutually exclusive. **Fix:** decide the model and implement/guard it.
- **BILL-9 (P2) — Porous deploy gate.** Access granted on a saved PM token (not a chargeable card) or a stale cached `subscription_status`; if an admin flips `managed_billing_enabled` off, campaigns spend real money with no charging. **Fix:** verify a chargeable PM against Stripe; don't allow spend when billing is disabled.
- **BILL-10 (P2/P3) — Misc:** `getBudgetMultiplier` checks `PAUSED` after `LOW_BALANCE` (paused low-balance returns 0.75 not 0.0); `retryPayment` flat-$50 for accounts paused >7d re-enters the failure cycle; float money math end-to-end; dunning would retry a dead card forever once BILL-2 is fixed (add a cap).

_Note: the deploy-time "charge full top-up ignoring existing credit" bug was fixed earlier this session (`setupForDeployment` now charges only the shortfall). The daily-billing idempotency/locking/recovery issues above are separate and remain._

## 3. Data model & migrations

- **DATA-1 (P0) — Dropped column breaks auth.** `customers.user_id` was dropped but is still read at `AttributionController:23`, `CampaignCopilotController:33,96,116` as `$campaign->customer?->user_id !== $user->id` → always true → blanket 403 on attribution + copilot (flipping the operator would be an auth *bypass*). **Fix:** use the pivot check `$user->customers()->where('customers.id',$campaign->customer_id)->exists()`.
- **DATA-2 (P0) — MCC token encryption gap (also a security hole).** Admin UI saves `MccAccount.refresh_token` encrypted, but `DataManagerService:153`, `RecordSiteGoogleConversion:116`, `UploadOfflineConversions:324`, `ProvisionConversionActions:282` read it raw; only `BaseGoogleAdsService` decrypts. Works today only because the active token comes from plaintext env. The moment an MCC is saved via admin, all server-side conversion uploads fail with `invalid_grant`. **Fix:** one `MccAccount::getDecryptedRefreshToken()` accessor used by all readers; do this together with encrypting `Connection.access_token/refresh_token` (plaintext today — DATA-6).
- **DATA-3 (P0) — Unlocked money ledger.** Same as BILL-3 from the schema side: `AdSpendCredit` decimal balance mutated without transaction/lock. **Fix:** locked transaction + integer cents (pattern exists in `plans.price_cents`).
- **DATA-4 (P1) — `NegativeKeywordList` insert violates NOT NULL `campaign_id`.** `KeywordController:272` inserts only `customer_id,name,keywords` → 500. **Fix:** make `campaign_id` nullable (migration); remove the superseded create migration.
- **DATA-5 (P1) — Postgres/MySQL mismatch.** `AttributionController:36` uses `JSON_EXTRACT(...)` (MySQL) on a Postgres DB → `QueryException` (currently masked by DATA-1). **Fix:** `whereJsonContains` or query the relational `attribution_touchpoints` table.
- **DATA-6 (P0/P1) — Plaintext OAuth tokens.** `Connection.access_token/refresh_token` plaintext, not hidden; `MccAccount` token plaintext; `customers.tracking_signing_secret`/`google_ads_refresh_token` plaintext. Correct pattern exists (`CrmIntegration` `encrypted:array`). **Fix:** `encrypted` casts + re-save migration + decrypting accessors.
- **DATA-7 (P1) — Money as `float`.** `microsoft_ads_performance_data` and `keywords.cost` use `float` while Google/FB/LinkedIn use `decimal(…,2)`; cross-platform `SUM()` loses precision. **Fix:** standardize on `decimal(12,2)` (or micros bigint).
- **DATA-8 (P2) — Free-text status enums / casing mismatch.** `campaigns.status` defaults `'DRAFT'` but code writes/queries `'active'` (casing mismatch → queries miss rows); three overlapping status columns with no state machine. **Fix:** backed PHP enums + DB CHECK (as done for `strategies.campaign_type`).
- **DATA-9 (P2) — Micros without int cast.** `CreateCampaign.php`, `PerformanceAnomalyAlertAgent:258` pass floats into int64 protobuf fields (`19.99*1e6 = 19989999.99…`). **Fix:** `(int) round($amount*1_000_000)` at every micros boundary.
- **DATA-10 (P2) — N+1 fan-out.** `DashboardController::buildCampaignBreakdown`, `RoiDashboardController`, `OptimizeCampaigns` run per-campaign aggregate queries / resolve plans per row without eager loading. **Fix:** `whereIn(...)->groupBy` + `with('customer.users')` (pattern already used in `MonitorCampaignStatus`).
- **DATA-11 (P2) — Migration hazards.** `fix_keyword_unique_constraint` does `DELETE FROM keywords` in a schema migration using Postgres-only `DISTINCT ON` (breaks sqlite default); `remove_foreign_keys` drops columns of data with an empty `down()`; duplicate/empty stub migrations; data seeding inside a migration. **Fix:** move destructive ops to reviewed data migrations/seeders; keep the sqlite test path working.
- **DATA-12 (P3) — Dual sources of truth & orphans:** `campaigns.keywords` JSON vs `keywords` table; `war_room_competitors` JSON vs `competitors`; `attribution_conversions.touchpoints` JSON vs indexed `attribution_touchpoints`; orphaned `customers.google_ads_refresh_token`; `BusinessManagerService:84` writes dropped `facebook_token_is_long_lived`; keyword unique-key vs upsert-key mismatch; missing FKs/indexes on `*_ads_campaign_id`, `keywords.added_by`.

## 4. Platform integrations (Google / Meta / Microsoft / LinkedIn)

- **PLAT-1 (P1) — Google client rebuilt per service instantiation.** `BaseGoogleAdsService` re-reads `google_ads_php.ini`, queries `MccAccount::getActive()`, decrypts, and builds a fresh gRPC client on every `new …Service()` — 60+ per campaign launch. **Fix:** a container-bound `GoogleAdsClientFactory` memoized per (customer, token); inject a built client.
- **PLAT-2 (P1) — API-version rot.** `V22` baked into ~100 `use` statements (Google deprecates ~every 4 months, no single constant). Facebook Graph version inconsistent: `v22.0` in base/token services but **`v18.0`** (retired) in `ConversionsApiService` + `BusinessManagerService`, `v19.0` in the legacy service. Meta will reject v18.0 → server-side FB conversions on borrowed time. **Fix:** hoist each platform version to config; align all FB services on one value; track the Google SDK deprecation date.
- **PLAT-3 (P1) — Rotting/wrong AI model IDs.** `DemoController:223` falls back to retired `gemini-1.5-flash-latest`; `KnowledgeBaseSearchService:28` hardcodes `gemini-embedding-2-preview`; `CampaignRemediationAgent:458` hardcodes an image-preview model; `config/ai.php` default embedding contradicts its own comment. Preview IDs rotate/shut down. **Fix:** route all model refs through `config('ai.models.*')`; prefer stable (non-`-preview`) IDs in prod.
- **PLAT-4 (P1) — Error handling by string-matching.** `RetryableApiOperation` decides retryable-vs-fatal via `str_contains` on English messages (quota errors mis-bucketed; any "billing" substring = permanently fatal); `isRateLimited()` only inspects arrays but Google throws and FB returns null → dead code; `usleep()` blocks the worker through backoff. **Fix:** categorize on the SDK's typed `errorCode`/HTTP status; honor `Retry-After`; use `release($delay)` for long backoffs.
- **PLAT-5 (P1) — Facebook failures collapse to `null`.** `BaseFacebookAdsService` returns `null` on any non-2xx, discarding `error.code`/subcode (190 token vs 17/80004 rate-limit vs 100 bad-param). `ConversionsApiService::sendEvents` never checks `events_received` vs sent → a `200` with `events_received:0` reads as success and `UploadOfflineConversions` marks those conversions uploaded. **Fix:** propagate the structured error/throw typed; compare `events_received` to batch size.
- **PLAT-6 (P2) — Duplicated logic:** `resolveDailyBudget` fallback (`daily_budget ?: campaign ?: total/30`) repeated ~10× (unguarded division, FB variant ×100 to cents vs Google micros — unit-mixup risk); per-platform base-service auth boilerplate duplicated; execution-agent helpers (`validateBudget`, `buildRecoveryPrompt`, `appendUtmParameters`) duplicated instead of on the base. **Fix:** extract helpers/base classes.
- **PLAT-7 (P2/P3) — Correctness edges:** `MicrosoftAds ConversionTrackingService::getConversionCountLast30Days` returns hardcoded `0` (bidding-strategy gate would never qualify); `CaptureClickIds` captures `msclid` but Bing's param is `msclkid` (verify — else Microsoft offline conversions never get a click id); `DataManagerService` sends DMA consent `GRANTED` unconditionally (EEA/UK compliance); `ConversionsApiService` ignores the per-user-token flag; `FetchGoogleAdsPerformanceData` passes a nullable customer id into the API with no guard (burns retries).

## 5. Job & queue reliability

- **JOB-1 (P0) — `ApplySeasonalStrategyShift` writes unclamped LLM budgets.** Gemini's `new_daily_budget` pushed to Google/FB with no bounds check; overwrites the baseline so it compounds monthly; season keys (`spring/summer/...`) don't match config (`black_friday/summer_sale`) so the deterministic path never runs — leaving only "monthly unclamped LLM budget rewrite"; whole `handle()` catches+logs so it always "succeeds"; not in the health monitor. **Fix:** clamp to ±% of an immutable baseline, align config keys, add run-tracing, rethrow in the catch.
- **JOB-2 (P0) — Billing job not idempotent / silent under-billing.** Same as BILL-3; plus per-customer failures are caught+logged so `onFailure` never fires and a customer failing daily is never billed. **Fix:** completion marker + idempotency key; notify when `failed>0`.
- **JOB-3 (P1) — `UploadOfflineConversions`:** `failed` rows never retried (transient Google outage = permanent data loss for Smart Bidding); Microsoft path calls `createEventConversionGoal` per conversion (mints duplicate *goals*, never uploads events); 200-row cap with no self-redispatch; per-platform status collapsed to one column. **Fix:** per-platform status filtering + retry with attempt counter + self-redispatch; use the real Microsoft offline-conversion upload API.
- **JOB-4 (P1) — `SyncCrmConversions` self-disables.** One CRM error sets `status='error'`; scheduler only dispatches `connected` → sync stops forever; a crash after `status='syncing'` is also skipped and never reset. **Fix:** schedule on `connected|error|syncing` with a staleness guard; reset status in `failed()`; alert on `error`.
- **JOB-5 (P1) — `withoutOverlapping()` on `Schedule::job()` guards only dispatch, not execution.** Unprotected: `MonitorCampaignStatus` (hourly, all campaigns × 4 APIs — interleaved `primary_status` writes + double notifications) and `ProcessDailyAdSpendBilling`. **Fix:** `ShouldBeUnique` or an internal cache lock on both.
- **JOB-6 (P1) — Monolithic `tries=1` jobs with timeouts < fan-out work.** `RunSelfHealingChecks` (`timeout=600`) and `AutomatedCampaignMaintenance` (~10 agents/campaign) run everything in one job; on SIGKILL-at-timeout the `finally` lock release never runs → the in-flight campaign's 3600s lock stays held → that campaign is *also* skipped next pass; the tail of campaigns is silently unprocessed. **Fix:** fan out one job per campaign (as `CheckCampaignPolicyViolations` already does); order by least-recently-processed; shrink lock TTLs.
- **JOB-7 (P1) — User-facing jobs leave the UI hanging on hard failure.** `GenerateStrategy` sets completion + notifies on in-band errors, but its `failed()` (crash/timeout) only logs → `strategy_generation_completed_at` stays null → UI polls forever. `DeployCampaign`: a timeout after remote campaign creation but before persisting `deployment_status` lets a re-deploy pass the guard and **create a duplicate live campaign spending real money**. **Fix:** mark model failed + notify in both `failed()` handlers; persist platform IDs as the first write after each remote create.
- **JOB-8 (P2) — Observability blind spots.** The (good) `AgentRun`/`MonitorAgentHealth` backstop added this session covers 16 optimization jobs but **not the money/data pipeline**: `ProcessDailyAdSpendBilling`, `UploadOfflineConversions`, `SyncCrmConversions`, `Fetch*PerformanceData`, `SendDailyPerformanceReports`, `SyncProductFeed`, `RecordSiteConversion`, `ApplySeasonalStrategyShift`. Stale performance-data fetches silently degrade every downstream optimizer. **Fix:** add `RecordsAgentRun` + monitor entries to these.
- **JOB-9 (P2) — Retry gaps:** `SendDailyPerformanceReports` (`tries=2`) double-sends emails on retry (no per-customer guard); conversion-attribution jobs (`RecordSite*`) have `tries=1` and only log upload failures (own-account attribution lost on transient errors — cheap `tries=3` fix).
